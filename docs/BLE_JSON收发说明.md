# BLE JSON 配置收发说明

当前 APP 发送普通 UTF-8 JSON，以真实换行字节 `0A`（`\n`）结束。不再添加 `@请求ID序号:` 包头，也不再等待应用层 `chunk_ack`。JSON 字段、请求 `id`、UUID 和 Wi-Fi/MQTT 配置结果事件不变。

## 发送流程

1. 蓝牙连接、服务发现和通知订阅完成后，请求 MTU 247。
2. 运行环境支持 `getBLEMTU` 时读取实际值；也接受设置接口明确返回的 `mtu` 数值。仅返回 `setBLEMTU:ok` 不代表实际长度已确认。
3. 以实际 ATT MTU 减去 3 字节作为载荷长度，本工程最多使用 244 字节。无法确认实际值、接口不支持或协商超时时，使用兼容载荷 20 字节。
4. JSON 加末尾换行在载荷范围内时只调用一次写入；超过范围才按 UTF-8 字节切片。整条请求最多 1024 字节，包含末尾换行。
5. 使用 `writeType: "write"`，等待系统写入回调；不把写入成功视为配网成功。分段之间保留 120ms 间隔，不无间隔连发。

120ms 间隔用于给当前 Arduino-ESP32 3.3.3 的延后 `onWrite()` 回调留出处理时间；它不是手机和蓝牙链路的无条件可靠性保证。真机仍需核对开发板打印的完整 JSON，并验证配置结果。无需分段的单次写入没有分段等待。

普通 Android App 的 MTU 设置接口可能只返回成功、不提供实际值，且没有 `getBLEMTU`；这种情况下会继续按 20 字节分段，不能把“申请了 247”当作“实际已协商到 247”。微信端在实际值可读取时可使用更大载荷。

## 开发板处理

开发板已经具备普通 JSON 接收入口：跨写入拼接字节，收到换行后打印 `[BLE JSON RX]` 和完整内容，再由 ArduinoJson 解析请求、校验字段并交给原有协调器。此次只增加 BLE 本地 MTU 设置，不改 Wi-Fi/MQTT 连接、密码校验、NVS 保存或失败回退逻辑。

固件仍保留旧 `@...` 分包接收代码，供旧版 APP 兼容；当前 APP 不走该分支。开发板结果通知仍保守按最多 20 字节一段发送，APP 收齐 JSON 行后处理，不要求通知与写入使用相同分段长度。

## 回复与异常

- 保留原来的 `wifi_connecting` / `wifi_connected` / `wifi_failed`、`mqtt_connecting` / `mqtt_connected` / `mqtt_failed` 和 `error`。
- 只将本次请求 ID 的回复交给页面；重新连接后忽略旧监听回调。
- 收到完整坏 JSON 时，消费坏帧，不让它留在缓存污染后续请求；接收缓存超过 1024 字节时丢弃至下一换行，新的配置请求会重新清理接收缓存。
- JSON 解析错误使用 `invalid_response`；页面处理已解析回复时抛异常使用 `reply_processing_failed`，不再混报“控制器回复格式错误”。控制台记录页面异常，避免吞掉真实错误。
- 写入超时或失败后停止，不自动整条重发；可能残留半条配置时，要求断开并重新连接蓝牙再提交。这样可让开发板清空未完成请求。
- 最终成功回包是结果依据，即使手机没有触发最后一次原生写入成功回调，也不覆盖已确认的成功。

## 更新与实机复测

APP 必须在 HBuilderX 重新运行或重新打包安装，旧 APK 不会自动替换 JS。开发板重新编译烧录后可使用新增 MTU 设置；旧固件的普通 JSON 入口仍可接收兼容分段。

依次检查：

1. 蓝牙重连后提交正常 Wi-Fi 配置；串口出现完整 JSON，APP 显示实际连接结果。
2. Wi-Fi 错误密码后改正确密码，再次成功，不能立即复用上一次失败结果。
3. 提交 MQTT 参数，确认收到 `mqtt_connected` / `mqtt_failed`；不把蓝牙写入当作服务器已连接。
4. 在手机日志中核对 `payload` 和 `packets`：长度足够时 `packets=1`，否则串行分段。
5. 中文、引号、反斜杠、较长 MQTT 参数、断开重连和系统写入失败后重连。

`[BLE JSON RX]` 按用户要求保留原文，**会包含明文 Wi-Fi/MQTT 密码**；分享串口日志前必须遮挡。APP 的发送日志仅记录 ID、序号、长度，不打印配置原文。

## 自动化测试

在 `uniapp-ble-provisioning` 目录运行 `node --test`。`tests/ble-json-transfer.test.mjs` 覆盖实际 MTU 单次/多次写入、协商失败、回调超时、延后收包模型、真实 Vue 响应式对象、坏 JSON 清理、旧监听隔离与页面异常分类。

固件主机测试沿用 `tools/verify-mqtt-configuration.ps1`；`tests/ble_received_json_test` 额外使用真实固件组帧器验证一次写入和 20 字节分段时收到同样的 MQTT 字段。自动化测试和构建不能替代手机与开发板实测。
