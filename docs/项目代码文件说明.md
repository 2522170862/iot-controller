# 项目代码文件说明

本文只说明源码文件的职责，以及其中函数/方法的用途。头文件（`.h`）负责声明接口、
常量和数据结构；同名实现文件（`.cpp`）负责完成具体逻辑。账号、密码等配置值不在本文展示。

## 入口与基础数据

### `iot-controller.ino`

**职责：** 项目主入口。创建全部模块对象，完成硬件初始化，并在 `loop()` 中轮询传感器、网络、MQTT、显示和执行器。

| 函数 | 功能 |
| --- | --- |
| `makeHash()` | 根据递增序列号和当前时间生成 MQTT 消息的 8 位 `hash`。 |
| `enqueueJson()` | 将 JSON 字符串封装为 `MqttMessage`，并放入普通发送队列或回执优先队列。 |
| `publishEnvironment()` | 生成并上报环境传感器与麦克风数据。 |
| `publishEncoder()` | 生成并上报编码器位置和按键状态。 |
| `publishJoystick()` | 生成并上报滤波后的摇杆 X/Y 值与按键状态。 |
| `publishRfid()` | 生成并上报新读取到的 RFID 卡 UID。 |
| `processCommand()` | 解析收到的 MQTT JSON，调用模块命令分发器，并生成执行回执。 |
| `setup()` | 初始化串口、状态灯、显示、传感器和执行器；选择 NVS 或默认 Wi‑Fi 凭据，并启动 BLE 配网、Wi‑Fi 与 MQTT。 |
| `loop()` | 高频轮询外设、BLE 配网事务、Wi‑Fi 与 MQTT；每 500 ms 汇总数据、处理指令、上报定时环境数据并刷新屏幕。 |

### `DashboardTypes.h`

**职责：** 定义模块之间共用的数据结构。

| 数据结构 | 功能 |
| --- | --- |
| `EnvironmentData` | 保存温湿度、气压、光照、海拔、麦克风、摇杆、编码器、RFID 和传感器在线状态。 |
| `NetworkStatus` | 保存 Wi‑Fi 是否连接、SSID、本机 IP 和 MQTT 主机地址等网络显示数据。 |

### `PeripheralPins.h`

**职责：** 统一定义 ESP32‑S3 外设 GPIO 编号，避免各模块各自硬编码引脚。

**主要常量：** 摇杆 GPIO1/2、Wi‑Fi 指示灯 GPIO3、继电器 GPIO4/5、编码器 GPIO6/7/38、麦克风 GPIO8、显示/RC522 SPI、RS485 GPIO17/18、RGB GPIO21、步进电机 GPIO39–42、MQTT 指示灯 GPIO43、BLE 指示灯 GPIO44，以及直流电机 GPIO47/48。

## 屏幕与状态指示

### `DashboardEventPolicy.h`

**职责：** 判断当前是否有需要优先显示的事件，包括摇杆、麦克风、编码器和 RFID。

| 函数/方法 | 功能 |
| --- | --- |
| `detect()` | 比较当前与上一次输入数据；检测到事件时记录事件类型和起始时间。 |
| `active()` | 判断当前事件是否仍在 3 秒显示时限内。 |
| `type()` | 返回当前应显示的事件类型；无活动事件时返回 `kNone`。 |
| `difference()` | 计算两个无符号数的差值，供摇杆阈值判断使用。 |
| `trigger()` | 开始一个事件计时。 |
| `remember()` | 保存本次输入状态，作为下一次比较基准。 |

### `DashboardView.h` / `DashboardView.cpp`

**职责：** 驱动 ST7789 屏幕，显示环境总览页和事件详情页。

| 函数/方法 | 功能 |
| --- | --- |
| `DashboardView()` | 创建 ST7789 显示对象并初始化页面状态。 |
| `begin()` | 初始化 SPI 与 ST7789 显示屏参数。 |
| `drawStaticLayout()` | 标记需要重新绘制固定页面框架。 |
| `update()` | 根据环境、网络与事件状态选择总览页或事件页，并更新动态数值。 |
| `notifyRfidReceived()` | 通知显示模块下次刷新时优先显示 RFID 事件。 |
| `gaugeSegmentsForPercent()` | 将湿度百分比换算为仪表盘应点亮的分段数量。 |
| `drawHeader()` | 绘制顶部标题与 Wi‑Fi 连接状态。 |
| `drawOverviewPage()` | 绘制温度、湿度、气压、光照、海拔、RS485 状态等总览布局。 |
| `drawEventPage()` | 绘制摇杆、麦克风、编码器或 RFID 的事件详情布局。 |
| `drawMetricCard()` | 绘制一张通用环境指标卡片。 |
| `drawHumidityGauge()` | 绘制湿度圆形分段仪表。 |
| `drawCardValue()` | 在环境指标卡片中刷新一项数值。 |
| `drawRow()` | 在事件详情页中绘制一行标签和值。 |
| `updateOverview()` | 刷新环境总览中的实时数据。 |
| `updateEvent()` | 刷新当前事件页面的实时数据。 |

### `ConnectionStatusIndicators.h` / `ConnectionStatusIndicators.cpp`

**职责：** 驱动 Wi‑Fi、MQTT 和 BLE 三盏高电平点亮的连接状态 LED。

| 函数/方法 | 功能 |
| --- | --- |
| `ConnectionStatusIndicators()` | 保存 Wi‑Fi、MQTT、BLE LED 引脚以及可注入的 GPIO 操作函数。 |
| `begin()` | 将三路 LED 设为输出并默认拉低熄灭。 |
| `update()` | 验证新 Wi‑Fi 时按 250 ms 周期切换 Wi‑Fi 灯；其余时间分别按 Wi‑Fi、MQTT、BLE 连接状态控制三盏灯。 |

## 环境传感器与输入模块

### `ModbusEnvironmentProtocol.h` / `ModbusEnvironmentProtocol.cpp`

**职责：** 定义三合一环境传感器的 Modbus RTU 协议，包含查询帧构造、CRC 校验和寄存器解析。

| 函数 | 功能 |
| --- | --- |
| `buildReadAllRequest()` | 构造地址 `0x01`、功能码 `0x03`、读取 `0x0065` 起 7 个寄存器的 8 字节请求帧。 |
| `parseReadAllResponse()` | 校验 19 字节应答的地址、功能码、字节数和 CRC；成功后写入光照、温度、气压、湿度与海拔。 |
| `calculateCrc()` | 内部函数，计算 Modbus RTU CRC‑16。 |
| `readUint16()` / `readUint32()` | 内部函数，按大端顺序读取传感器寄存器数值。 |

### `Rs485EnvironmentDataSource.h` / `Rs485EnvironmentDataSource.cpp`

**职责：** 使用 ESP32 的 `HardwareSerial(2)` 通过 RS485‑TTL 转换模块周期性读取环境传感器。

| 函数/方法 | 功能 |
| --- | --- |
| `begin()` | 以 9600、8N1 启动 UART2，RX 为 GPIO18、TX 为 GPIO17。 |
| `poll()` | 状态机：每 1 秒发送一次请求，收集应答，完整帧交给 Modbus 解析器，并在 150 ms 超时时标记离线。 |
| `readEnvironment()` | 返回最近一次环境数据和传感器在线状态。 |
| `startReadRequest()` | 清除残留串口数据，构造并发送 Modbus 查询帧。 |
| `resetResponse()` | 清空当前应答缓冲区长度。 |

### `JoystickInputDataSource.h` / `JoystickInputDataSource.cpp`

**职责：** 读取 PS2 摇杆的 X/Y 模拟量。

| 函数/方法 | 功能 |
| --- | --- |
| `JoystickInputDataSource()` | 保存 ADC 读取函数，便于硬件测试时替换。 |
| `begin()` | 将 GPIO1、GPIO2 配为 12 位 ADC，并设置 11 dB 衰减。 |
| `readInto()` | 将 X/Y 各连续采样 16 次并取平均值后写入 `EnvironmentData`；当前不使用摇杆按键，因此 `joystickPressed` 固定为 `false`。 |
| `readFilteredAxis()` | 内部函数，计算指定摇杆轴 16 次 ADC 采样的平均值。 |

### `MicrophoneInputDataSource.h` / `MicrophoneInputDataSource.cpp`

**职责：** 采样 MAX4466 模拟输出，并将采样窗口内的峰峰值换算为 0–100 的声音强度。

| 函数/方法 | 功能 |
| --- | --- |
| `MicrophoneInputDataSource()` | 保存 ADC 读取函数。 |
| `begin()` | 将 GPIO8 配为 12 位 ADC，并设置 11 dB 衰减。 |
| `poll()` | 每 250 µs 采样一次；连续 64 个样本后计算峰峰值并更新声音百分比。 |
| `readInto()` | 将最近计算的声音百分比写入 `EnvironmentData`。 |
| `levelFromPeakToPeak()` | 将 ADC 峰峰值按噪声门限和最大响度门限换算为百分比。 |

### `RotaryEncoderInputDataSource.h` / `RotaryEncoderInputDataSource.cpp`

**职责：** 读取 EC11 旋转编码器的 A/B 相与按键，维护累计位置。

| 函数/方法 | 功能 |
| --- | --- |
| `RotaryEncoderInputDataSource()` | 保存数字输入读取与 GPIO 模式设置函数。 |
| `begin()` | 将 A、B、按键 GPIO 配置为内部上拉输入，并读取初始两相状态。 |
| `poll()` | 根据两相状态转换表累积旋转变化；每满 4 个边沿更新一次位置。 |
| `readInto()` | 将累计位置和低电平有效的按键状态写入 `EnvironmentData`。 |
| `readState()` | 读取 A/B 相并编码为两位状态值。 |

### `RfidReader.h` / `RfidReader.cpp`

**职责：** 驱动 RC522 读卡器，检测新卡并保存 UID 文本。

| 函数/方法 | 功能 |
| --- | --- |
| `RfidReader()` | 以 SS、RST 引脚创建 MFRC522 对象。 |
| `begin()` | 初始化 RC522，打印固件版本并报告 SPI 通信是否正常。 |
| `poll()` | 检测新卡、读取卡序列号、保存 UID，并结束本次卡通信；读取成功返回 `true`。 |
| `hasCard()` | 返回是否已成功读到过卡。 |
| `cardUid()` | 返回最近读到的 UID；尚未读卡时返回空指针。 |
| `storeUid()` | 将 RC522 的 UID 字节格式化成冒号分隔的十六进制文本。 |

### `MockDataSource.h` / `MockDataSource.cpp`

**职责：** 提供不依赖真实硬件的模拟环境与网络数据，主要用于界面和单元测试。

| 函数/方法 | 功能 |
| --- | --- |
| `readEnvironment()` | 按不同周期生成温度、湿度、气压、光照、麦克风和摇杆的变化数据。 |
| `readNetwork()` | 返回固定的模拟网络状态。 |
| `triangleWave()` | 内部函数，生成 0–1 的三角波。 |

## 网络与 MQTT

### `WifiCredentials.h`

**职责：** 保存 Wi‑Fi SSID 与密码常量，供 Wi‑Fi 模块连接使用。

**函数：** 无。

### `WifiCredentialStore.h` / `WifiCredentialStore.cpp`

**职责：** 校验 Wi‑Fi 凭据并使用 ESP32 Preferences 在 NVS 中保存最后一次验证成功的网络。

| 函数/方法 | 功能 |
| --- | --- |
| `WifiCredentialPolicy::isValid()` | 按 UTF‑8 存储长度上限校验非空 SSID 和 0–63 字节密码。 |
| `WifiCredentialPolicy::selectBootCredentials()` | 有有效 NVS 凭据时优先使用，否则选择编译期默认凭据。 |
| `load()` | 从 `iot_wifi` 命名空间读取并验证凭据。 |
| `save()` | 将新凭据写入非活动槽，完整成功后才原子切换活动槽，避免写入失败破坏旧凭据。 |
| `clear()` | 清空 `iot_wifi` 命名空间中的配网记录。 |

### `MqttCredentials.h`

**职责：** 保存 MQTT 服务器地址、端口、用户名、密码、收发主题、QoS 和客户端 ID 常量。

**函数：** 无。

### `WiFiDataSource.h` / `WiFiDataSource.cpp`

**职责：** 管理 ESP32 Wi‑Fi 连接、自动重连和网络状态输出。

| 函数/方法 | 功能 |
| --- | --- |
| `WiFiDataSource()` | 初始化离线状态和默认 IP。 |
| `begin()` | 设置 STA 模式、启用自动重连并使用默认或指定凭据发起首次连接。 |
| `poll()` | 检查 Wi‑Fi 状态；连接成功时记录 IP，断开后按 10 秒间隔重连。 |
| `readNetwork()` | 返回用于显示的 `NetworkStatus`。 |
| `connect()` | 保存一组待验证凭据并立即发起切换。 |
| `currentCredentials()` | 返回当前尝试使用的凭据，供失败回滚。 |
| `attemptState()` | 返回空闲、连接中、已连接或失败状态。 |
| `localIp()` | 返回最近获取的本机 IPv4 文本。 |
| `startConnection()` | 内部函数，调用 `WiFi.begin()` 发起连接。 |
| `setLocalIp()` | 内部函数，安全复制 IP 字符串。 |

### `BleProvisioningProtocol.h` / `BleProvisioningProtocol.cpp`

**职责：** 定义 BLE 配网 UUID、JSON 行协议、20 字节分包边界、接收缓存与固定容量请求队列。

| 函数/方法 | 功能 |
| --- | --- |
| `BleProvisioningProtocol::parseRequest()` | 解析并校验 8 位 ID、命令、SSID 和密码。 |
| `BleProvisioningProtocol::makeEvent()` | 生成带请求 ID 的连接中、成功、失败或协议错误 JSON 行。 |
| `BleProvisioningFrameAssembler::append()` | 跨 BLE 分包累积字节，遇到换行后解析一条完整请求。 |
| `BleProvisioningFrameAssembler::reset()` | 清空未完成消息。 |
| `BleProvisioningRequestQueue::push()` | 将完整请求加入固定容量队列。 |
| `BleProvisioningRequestQueue::pop()` | 取出最早的一条请求。 |
| `BleProvisioningRequestQueue::size()` | 返回当前请求数量。 |
| `BleProvisioningRequestQueue::clear()` | 清空全部待处理请求。 |

### `WifiProvisioningCoordinator.h` / `WifiProvisioningCoordinator.cpp`

**职责：** 在主循环中非阻塞执行新 Wi‑Fi 验证事务，成功才保存 NVS，失败则恢复原网络。

| 函数/方法 | 功能 |
| --- | --- |
| `WifiProvisioningCoordinator()` | 注入 Wi‑Fi 连接接口和凭据存储接口。 |
| `start()` | 接受一条配网请求，保存旧凭据、切换新网络并生成连接中事件。 |
| `poll()` | 检查连接、失败和 15 秒超时；成功保存，失败回滚。 |
| `active()` | 返回当前是否正在验证新网络。 |
| `takeEvent()` | 取出一条待发送给 BLE 客户端的事务事件。 |
| `finishFailure()` | 内部函数，恢复旧凭据并生成失败事件。 |
| `pushEvent()` | 内部函数，将事件加入固定容量队列。 |

### `BleProvisioningService.h` / `BleProvisioningService.cpp`

**职责：** 在 ESP32-S3 上提供 `IoT-Controller-XXXX` BLE GATT 服务，接收配网请求并分包通知结果。

| 函数/方法 | 功能 |
| --- | --- |
| `begin()` | 创建固定 UUID 的服务、RX/TX 特征值并开始广播。 |
| `poll()` | BLE 断开后恢复广播，并按最多 20 字节发送一段通知。 |
| `connected()` | 返回 BLE 客户端是否连接。 |
| `takeRequest()` | 从回调请求队列取出完整配网请求。 |
| `enqueueEvent()` | 把协调器事件编码为 JSON 行并加入通知队列。 |
| `onConnected()` / `onDisconnected()` | 更新连接状态、串口日志和重新广播状态。 |
| `onWrite()` | 处理 RX 分包、组帧、协议错误和请求入队。 |
| `enqueueFrame()` | 内部函数，将完整通知帧放入发送队列。 |
| `enqueueProtocolError()` | 内部函数，生成协议错误通知。 |
| `clearOutgoing()` | 清空尚未发送完的 BLE 通知。 |

### `MqttConnectionState.h`

**职责：** 仅负责 MQTT 重连尝试的时间节流。

| 函数/方法 | 功能 |
| --- | --- |
| `shouldAttempt()` | Wi‑Fi 已连接且距上次尝试至少 5 秒时返回 `true`。 |
| `recordAttempt()` | 记录一次 MQTT 连接尝试时间。 |
| `reset()` | Wi‑Fi 断开后清除尝试状态，使恢复 Wi‑Fi 后可立即重连。 |

### `MqttMessageQueue.h` / `MqttMessageQueue.cpp`

**职责：** 实现固定容量的 MQTT 消息 FIFO 队列；上行回执优先于遥测。

| 函数/方法 | 功能 |
| --- | --- |
| `push()` | 将普通消息加入队尾；队满时返回 `false`。 |
| `pushReply()` | 加入回执；队满时优先移除最早的非回执消息，为回执腾出空间。 |
| `pop()` | 取出并删除最早的一条消息。 |
| `size()` | 返回当前队列消息数量。 |
| `eraseAt()` | 内部函数，删除指定位置的消息并前移后续元素。 |

### `MqttMessageProtocol.h` / `MqttMessageProtocol.cpp`

**职责：** 定义 MQTT 命令类型，解析 JSON 指令并校验参数范围。

| 函数/方法 | 功能 |
| --- | --- |
| `parseCommand()` | 解析 `relay`、`rgb`、`servo`、`stepper`、`dc_motor`、`input` 指令，写入统一的 `MqttCommand`。 |
| `generateHash()` | 以 FNV‑1a 算法由序列号和时间生成 8 位十六进制 `hash`。 |
| `isHash()` | 内部函数，校验 `hash` 是否为 8 位十六进制字符。 |
| `readInt()` | 内部函数，读取并校验 JSON 中有范围要求的整数。 |

### `MqttService.h` / `MqttService.cpp`

**职责：** 封装 PubSubClient，处理 MQTT 建连、订阅、收包、发包及收发队列。

| 函数/方法 | 功能 |
| --- | --- |
| `begin()` | 设置 MQTT 服务器、消息缓冲区和接收回调。 |
| `poll()` | Wi‑Fi 离线时断开 MQTT；在线时按重连策略连接；连接后执行 `client.loop()` 并发布一条待发消息。 |
| `takeIncoming()` | 从接收队列取出一条服务端下发消息。 |
| `enqueue()` | 将普通遥测消息放入发送队列。 |
| `enqueueReply()` | 将命令回执放入优先发送队列。 |
| `connected()` | 返回当前 MQTT 是否连接。 |
| `onMessage()` | PubSubClient 静态回调入口，转交给当前服务实例。 |
| `copyIncoming()` | 检查主题与负载长度后，将收到的 MQTT 消息复制到接收队列。 |
| `connectAndSubscribe()` | 使用配置中的客户端身份连接服务器，并订阅下行主题。 |
| `publishOne()` | 从发送队列取一条消息发布；发布失败时放回队列。 |

### `MqttTelemetrySchedule.h`

**职责：** 集中定义 MQTT 主动上报的触发条件。

| 函数/方法 | 功能 |
| --- | --- |
| `environmentDue()` | 判断距离上次环境数据上报是否已达到 20 秒。 |
| `encoderChanged()` | 判断编码器位置或按键状态是否变化。 |
| `joystickChanged()` | 判断摇杆任一轴相对上次上报值的变化量是否大于 20。 |

## MQTT 模块控制与执行器

### `ModuleCommandDispatcher.h` / `ModuleCommandDispatcher.cpp`

**职责：** 将已解析的 `MqttCommand` 分发至继电器、RGB、舵机、步进电机或直流电机，并返回统一执行结果。

| 函数/方法 | 功能 |
| --- | --- |
| `ModuleCommandDispatcher()` | 保存各执行器对象指针。 |
| `dispatch()` | 根据命令类型调用对应模块；处理模块缺失、步进电机忙碌等情况，并返回 `ok` 与状态文本。 |

### `RelayController.h` / `RelayController.cpp`

**职责：** 控制低电平触发的两路继电器。

| `begin()` | 配置继电器引脚并确保上电默认两路关闭。 |
| `setChannel()` | 开启或关闭指定的第 1/2 路继电器。 |

## `uniapp-ble-provisioning/` 手机配网工程

### `utils/protocol.js`

**职责：** 提供与固件一致的 BLE UUID、请求 ID、UTF‑8 JSON 行编码、20 字节分包和通知解码。

| 函数/方法 | 功能 |
| --- | --- |
| `createRequestId()` | 生成 8 位小写十六进制请求 ID。 |
| `concatChunks()` | 将多个字节分包合并为一个 `Uint8Array`。 |
| `encodeWifiRequest()` | 校验字段，生成 `configure_wifi` JSON 行并切成最多 20 字节的分包。 |
| `isReplyForRequest()` | 判断通知是否属于当前请求。 |
| `provisioningFailureReason()` | 识别固件失败/协议错误事件并返回原因。 |
| `JsonLineDecoder.push()` | 使用流式 UTF‑8 解码，返回当前数据中全部完整 JSON 行。 |
| `JsonLineDecoder.reset()` | 清空残留文本和 UTF‑8 解码状态。 |

### `services/ble-service.js`

**职责：** 封装 UniApp BLE 初始化、控制器扫描、连接、服务发现、通知订阅、串行写入和资源清理。

| 函数/方法 | 功能 |
| --- | --- |
| `scan()` | 搜索名称以 `IoT-Controller-` 开头的设备，并按信号强度返回列表。 |
| `connect()` | 连接设备、发现固定 UUID 服务和特征值，并启用通知。 |
| `sendWifiCredentials()` | 生成请求 ID，将 SSID/密码按 20 字节分包顺序写入 RX。 |
| `close()` | 停止扫描、移除监听、断开连接并关闭蓝牙适配器。 |
| `openAdapter()` | 确保蓝牙适配器已初始化。 |
| `stopDiscovery()` | 停止当前蓝牙设备发现。 |
| `installConnectionListeners()` | 注册通知和断开事件监听，并按请求 ID 分发消息。 |
| `removeDeviceFoundListener()` | 移除设备发现监听。 |
| `removeConnectionListeners()` | 移除通知和连接状态监听。 |
| `resetConnection()` | 清空连接标识、特征值和解码器状态。 |

### `services/wifi-service.js`

**职责：** 调用微信小程序或 Android 手机的 Wi‑Fi 扫描能力，并统一附近网络列表。

| 函数/方法 | 功能 |
| --- | --- |

| `initialize()` | 申请平台权限、启动 Wi‑Fi 模块并注册列表监听。 |
| `scan()` | 触发一次手机 Wi‑Fi 扫描，并在超时前返回标准化结果。 |
| `close()` | 取消扫描、移除监听并停止 Wi‑Fi 模块。 |
